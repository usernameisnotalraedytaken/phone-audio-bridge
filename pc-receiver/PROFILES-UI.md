# 配置编辑器（计划 ⑤）

**代码**：`SnadProfileForm.cs`（界面）、`SnadProfile.cs`（持久化与估算模型）、
`SnadProfileShot.cs`（自渲染检查）

---

## 一、为什么这一版是重做的

第一版在 ③④ 之前就做了，结果是：
- 字段表里没有 `buffer_mode` / `min` / `max` / `adapt_rate`（③ 还没做）
- 显示的延迟是 386 / 421 / 1052 ms，而那三个数已被回环实测推翻

计划 §7 早就写了"⑤ 最后做，先做必然返工"。这一版按 ③④ 的实际参数重建。

## 二、延迟模型已改正

旧公式把 `WaveOutBuffers × BlockMs`（balanced 256 ms、highquality 672 ms）
当成延迟相加。回环实测表明该项在稳态下并不存在（见 `LATENCY-MEASURED.md`）。

新模型四项，每项都标出是实测还是估计：

```
capture [上报值或 ~8] + net ~21 + buffer [配置] + output [实测值或 ~29/44]
```

界面上带 `~` 的表示估计，不带的是实测或配置值。balanced 显示 **~138 ms**
而不是原来的 421 ms。

## 三、按"改了要不要重开流"分组

两列分别是 `APPLIES IMMEDIATELY`（边听边调）与 `NEEDS RESTART`（保存后流会重开）。
分组由字段的 `Restart` 标记自动划分，不再手写键名列表——
前一版手写列表时出现过"live 组里混进需重启项"的自相矛盾。

## 四、不可用项给出原因（计划 §4.4）

后端不适用或被设备限制的控件会压暗，并在界面上写清原因，例如：

```
禁用原因：waveOut 固定 pcm16，位深不可选；WASAPI 周期对 waveOut 无效
```

独自灰掉一个控件等于让用户去猜，而原因恰恰无法从界面推断。

## 五、操作（计划 §4.5）

左侧七个（档位生命周期）：`NEW` `COPY` `RENAME` `DELETE` `RESET` `EXPORT` `IMPORT`
右侧两个（本次编辑）：`REVERT` `SAVE`

- **RENAME**：先写新段再删旧段，中途失败可回滚，不会两头落空
- **RESET**：内置档位回退到代码里的默认值；自定义档位以 balanced 为底并保留名字与 EQ
- **EXPORT**：导出可直接拼回 `receiver.cfg` 的配置片段
- **IMPORT**：同名档位询问是否覆盖，不静默替换

## 六、持久化

新增键：`buffermode` `minbuffer` `maxbuffer` `adaptrate` `calibratesec`
`outputleg` `calibratedon` `capturebuffer`。
`SnadConfigTest` 已覆盖这八项的往返，以及"二次保存不产生重复键"。

`CloneFor` 改为逐字段复制——它此前漏掉了新字段，保存时会把它们清零，
而界面上看不出异常。

### 顺带修掉的三个工具缺陷

1. **按启发式找控件**：原先用"项数最多"猜设备下拉，加了 BUFFER MODE 后
   立刻认错控件。改为给控件命名（`field:<键名>`）后按名精确查找。
2. **最小尺寸写死**：加入 5 个策略字段后，最小尺寸下左列最后一行被裁掉
   （截图可见 RATIO MAX 只剩半行）。改为按内容计算，并留一行余量。
3. **`f.Close()` 阻塞**：它在最后一项检查之后卡住主线程，导致结论行永远打不出来，
   看起来像"检查没跑完"。改为隐藏窗体后直接退出。

## 八、采样率（计划 §1.1）

新增 `samplerate`：`follow`（跟随手机送来的采样率，默认）或具体数字。

**本版没有重采样**，所以指定值与源不一致时的行为必须说清楚：

- 不会悄悄跟随源 —— 那会让"我设了 44100"变成一句空话
- 不会强行按错误速率播放 —— 那会变调
- 而是**明确报错并停止**，日志写清两个值与该改哪里：

```
采样率不符：手机送来 48000 Hz，档位要求 44100 Hz。
本版没有重采样，无法转换；请把档位的采样率改为 follow 或改成与手机一致的值。
```

保存时也会在配置检查里提示"固定采样率会在不匹配时拒绝启动"。

### 顺带修掉一个会掩盖真实原因的缺陷

`Logger.Err(what, ex)` 对 `ex` 直接解引用。上面的报错最初传了 `null`，
结果这条明确的信息被 `NullReferenceException` 盖掉，日志里只剩
"接收循环异常 -> NullReferenceException"，看不出是采样率问题。

日志函数不该因为参数缺失把调用方打崩，因此 `ex` 允许为 null。
教训：**报错路径本身也要能被信任**，否则它会把最需要的信息吃掉。
