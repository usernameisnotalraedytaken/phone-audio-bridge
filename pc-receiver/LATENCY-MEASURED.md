# 输出后端延迟实测

**测量日期**：2026-10-17
**机器**：Realtek 板载声卡（设备序号 5）+ Voicemeeter 虚拟设备
**采样率**：48000 Hz，2 声道

本文所有数字都是**实测**，不是按配置算出来的。测量工具：
`SnadWaveOutTest.exe`（waveOut）与 `SnadWasapiTest.exe`（WASAPI）。

---

## 结论

| 后端 | 配置 | 声卡侧在飞 | 欠载 |
|---|---|---|---|
| **waveOut** | 16ms × 16 个（**当前 v2.0 配置**） | **256.00 ms** | 0 |
| waveOut | 16ms × 4 个 | 63.91 ms | 0 |
| waveOut | 16ms × 2 个 | 32.00 ms | 0 |
| waveOut | 8ms × 3 个 | 23.92 ms | 0 |
| waveOut | 4ms × 4 个 | 16.00 ms | 0 |
| **WASAPI 共享** | 缓冲 20ms | **10.33 ms** | 0 |
| WASAPI 独占 pcm24 | 周期自适应，缓冲 3ms | 13.17 ms | 0 |
| WASAPI 独占 pcm24 | 周期 3ms，缓冲 6ms | 15.93 ms | 0 |

### 核心发现

**1. 当前配置的 256ms 里有 240ms 是白付的。**
waveOut 的池子会稳定爬到**最满**且从不饿死——无论池子多深，
它都会填满。也就是说"16 个缓冲"不是一个必要的安全余量，
而是一个**不会被动用的余量**：实测 2 个缓冲也零欠载。
这意味着只靠调小 block 与池深度，就能从 256ms 降到 16ms。

**2. WASAPI 的优势是约 40%，不是数量级。**
实测 10.33ms（共享）对比 waveOut 最好的 16.00ms。
先前"缩小到 1/16"的说法是错的——那是拿 waveOut 的**配置容量**（256ms）
去比 WASAPI 的**实测值**（16ms），口径不一致。
同为实测值，差距是 1.6 倍。

**3. 独占模式并不比共享更快（本机）。**
独占 13.17~15.93ms，共享 10.33ms。独占的价值在于
**绕开系统混音器**（不被系统做音量/增强处理），不在于更低延迟。
这与"独占一定更快"的常见说法不同，但数据如此。

## 踩到的坑（都已修，记录以免重犯）

| 现象 | 原因 |
|---|---|
| `SetEventHandle` 返回 `0x88890001 NOT_INITIALIZED` | 必须在 `Initialize` **之后**调用 |
| 独占模式一律 `0x88890013` / `0x88890016` | 独占模式**不接受 `EVENTCALLBACK` 标志**，去掉即成功；改用轮询 |
| 探测第二个组合就 `0x8889000A DEVICE_IN_USE` | 未显式 `ReleaseComObject`，设备被上一个客户端占住 |
| `GetMixFormat` 的位深读错 | 必须按 `WAVEFORMATEXTENSIBLE` 整体读取才能拿到 `SubFormat`；只读基础结构会靠位深猜，而 32bit 容器既可能是 float 也可能是整数 |
| waveOut 测试量到"96% 池空" | 测试没有重新提交缓冲，池子一次性排空；真实行为是循环提交 |

## 复现方式

```powershell
cd pc-receiver

# waveOut：块大小、池深度、秒数
.\SnadWaveOutTest.exe -1 16 16 8     # 当前配置 -> 256ms
.\SnadWaveOutTest.exe -1 4 4 8       # 浅池浅块 -> 16ms

# WASAPI：设备序号、模式、格式、周期、秒数
.\SnadWasapiTest.exe 5 shared pcm16 20 6
.\SnadWasapiTest.exe 5 exclusive pcm24 3 6

# 独占模式的穷举探测（哪些组合真的可用）
.\SnadExclusiveProbe.exe 5
.\SnadExclusiveProbe.exe simple 5
```

## 尚未验证

- **长时间稳定性**：以上均为 6~8 秒样本。4ms 块或 2 个缓冲的配置
  在数分钟尺度上是否仍零欠载，需要更长的跑测才能下结论。
  短样本只能说明"可行"，不能说明"可靠"。
- **独占模式下的系统干扰**：独占会占住设备，其他程序在此期间无法使用。
  该影响未在实测中体现（测试期间仅本进程用设备）。
- **DAC 之后到实际出声**：以上测的都是"写入后端"到"设备取走"，
  不含数模转换与功放延迟。要测那段需要麦克风物理回环。
