# 端到端延迟测量：时间基准协议

**目标**：测出「手机采集音频 → 电脑目标设备播出」的真实延迟，而不是估计值。

---

## 1. 三个时间点

| 符号 | 含义 | 来源 | 现状 |
|---|---|---|---|
| `T_cap` | 手机采集该样本的时刻 | 音频包头 offset 14（手机单调时钟 ms） | 协议里一直有，**PC 端刚接上** |
| `T_play` | 该样本真正被设备播出的时刻 | waveOut 缓冲完成回调 | **未实现** |
| `Δ` | 两台机器的时钟差（PC − 手机） | 信标往返校准 | **未实现**（现用下界估计） |

```
端到端延迟 = (T_play − T_cap − Δ) + 手机采集缓冲
```

三项缺一不可。`Δ` 是唯一必须跨设备求的量。

---

## 2. 时钟差：为什么必须往返

只靠单程无法区分「网络慢」与「时钟差」。设真实单程时延为 `d`：

```
到达 − 采集 = Δ + d
```

一个方程两个未知数。往返可以消掉 `d`：

```
PC 发出        T1(PC)
手机收到        R(phone)
手机回发        S(phone)
PC 收到        T4(PC)

RTT    = (T4 − T1) − (S − R)          ← 扣掉手机内部处理时间
Δ ≈ T1 + RTT/2 − R                 ← 假设来回时延对称
误差   = (去程 − 回程)/2
```

**误差来源写在这里**：往返不对称时误差是两者差的一半，局域网通常 < 2 ms。
不能用「单向下界」冒充：那个估计的误差恒为正，会让延迟系统性偏小。

## 3. 报文

复用现有信标通道（UDP 6983），沿用 `SNADBEAC` magic 与 HMAC 校验，
新增两个**类型字节**，不改变原信标布局：

```
probe  PC → 手机
  0..7    "SNADBEAC"
  8       version = 1
  9       type = 'T'
  10..13  nonce        u32   每次探测递增，回复必须原样带回
  14..17  t1Ms         u32   PC 发送时刻（毫秒低 32 位）
  18..49  HMAC-SHA256(key, 前 18 字节)

reply  手机 → PC
  0..7    "SNADBEAC"
  8       version = 1
  9       type = 't'
  10..13  nonce        u32   原样带回
  14..17  t1Ms         u32   原样带回（PC 无需保存）
  18..21  recvMs       u32   手机收到 probe 的时刻
  22..25  sendMs       u32   手机发出 reply 的时刻
  26..57  HMAC-SHA256(key, 前 26 字节)
```

使用 u32 毫秒是刻意的：两端单调时钟都只有 32 位可用，且差值才是我们要的，
不必处理 64 位溢出。**但**跨 49.7 天回绕时差值会跳变——校准时若
`T4 − T1` 为负或异常大，直接丢弃该次样本并重试，不做任何"修正"。

`nonce` 与 HMAC 一起防伪造；回复原样带回 `t1Ms` 让 PC 无需保存状态。

---

## 4. 校准策略

- 每次连接开始时连续探测 8 次（间隔 200 ms），取 **RTT 最小**的那次
- 运行中每 30 秒补一次，用指数平均平滑 `Δ`，但**只接受 RTT < 中位数×1.5** 的样本
- 校准结果与样本数写进周期日志：`[时钟] Δ=1234.5 ms（基于 8 次，RTT 最小 3.1 ms）`
- 若 60 秒内拿不到任何样本，日志明确写「时钟未校准，端到端延迟不可用」，
  **不退回下界估计冒充实测**

## 5. 播出时刻 T_play

waveOut 路径：

1. 每次 `waveOutWrite` 记录 `(缓冲序号, 提交时刻, 该缓冲首帧的全局帧号)`
2. `WOM_DONE` 回调时记录完成时刻 → 该缓冲最后一帧的播出时刻
3. 缓冲内第 k 帧的播出时刻 = 完成时刻 − (剩余帧数 ÷ 采样率)
4. 入包时记下每包的 `(T_cap, 首帧全局帧号)`，与上面的映射相减即得 `T_play − T_cap`

WASAPI 路径（基线没有，将来若有）用 `IAudioClock` 的播放位置换算。

## 6. 验证：必须能测出已知延迟

**这是"可测量"的唯一判据。**

在手机发送路径注入一个可配置延迟 τ（0 / 50 / 100 / 200 ms），
每次测得的端到端延迟必须相应变化 τ，误差 ≤ 5 ms。

做不到这一点，说明测量链里还有未识别的常量，数字不可信。

τ 注入只在调试构建里存在，默认 0，且必须写进日志（避免"打开了忘记关"）。
