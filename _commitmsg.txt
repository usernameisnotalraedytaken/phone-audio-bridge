修复根源：EQ 曲线依赖播放才能显示

现象：打开均衡器窗口，不管推子怎么动，曲线始终是一条直线。
推子与读数都正常，说明数据确实改到了，只有曲线不动。

根因是环环相扣的三处：
  _sampleRate 初值为 0
  ResponseDb 在 _sampleRate <= 0 时直接 return 0   -> 频响恒为 0，即全平
  Rebuild   在 _sampleRate <= 0 时直接 return     -> 滤波器系数根本没算
而 Configure 全项目只在 WaveOut.Play 里被调用，也就是必须"开始播放"
才会给 EQ 采样率。但 EQ 的频响只取决于滤波器参数，与是否在放音无关，
这个依赖本身就不该存在。

修法：
- Equalizer._sampleRate 默认 48000，不再是 0。
  未配置时也能算出正确频响、也能试听。
- MainForm 打开 EQ 窗口前用接收器的实际采样率 Configure 一次，
  让曲线与实际听到的一致（44.1k 与 48k 的系数不同）。
  取不到时退回 48k。

漏测原因：检查工具里我预先调了 Configure(48000, 2)，
所以测试通过而真实路径是坏的——测的不是真实场景。
新增 CheckWorksWithoutConfigure 专门覆盖这条路径，
断言"不调 Configure 也能算出随设置变化的频响"。

顺带修正该断言里一个错误期望：105Hz 是低架滤波器，
架上增益 +12 时转折频率处恰为一半即 +6，直接期望 +12 会误判。
改为与全平基准比较，与滤波器类型无关。
